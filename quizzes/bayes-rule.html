Bayes' rule

Misconception quiz

Five questions on Bayes' rule. Every wrong option is a misconception people actually hold. Pick one. The note says why that choice was tempting, and what is going on instead.

1. In Bayes' rule, what is the prior?

The prior is your probability for each hypothesis before this piece of evidence. The evidence updates it. The prior is not a property of the test.

Printed accuracy is a percent you are given up front, so it feels like what you start with. Accuracy describes how the test behaves. The prior describes how common the hypotheses were before you saw this result.

That quantity is the marginal probability of the evidence, the thing you divide by so the posteriors add to 1. It is not the prior. It is also not a single shared constant you can skip: you compute it from the priors and the likelihoods.

Holding the result makes that number seem to be the starting point. The result is the evidence. The prior is what you believed before it arrived.

2. A condition is uncommon. A test is called 99% accurate, and this person's result is positive. Which claim is right?

Hearing "99% accurate" sounds like "99% chance this positive is a true one," as if accuracy were the chance you have the condition. Accuracy is about how often the test is right across people. When the condition is rare, most people who test positive can be healthy people who set off a false alarm. Your chance is the positive predictive value, and it can sit far below 99%.

Count the groups. In a large healthy group, a small false-alarm rate still produces many positive results. The sick group is small, so its true positives can be fewer than those false alarms. Bayes' rule is that comparison. It is not the accuracy number relabeled as your personal chance.

Seeing two percents at the start makes the accuracy seem to be the prior. The prior is how common the condition was before this test. Accuracy is not that prevalence, and a real result does update the prior.

Multiplying two 99% figures feels like combining independent chances. Multiplying the accuracy by itself is not Bayes' rule. You need the prior and both kinds of error, then you normalize.

3. A test is very likely to be positive if someone has the condition. What is that statement?

The chance of a positive result if they have the condition is a likelihood. Bayes' rule turns it into the chance they have the condition given a positive only together with the prior and the false-alarm rate. A high likelihood is not itself the posterior.

Reversing the two sentences feels harmless in ordinary speech. Those two probabilities are not equal. Swapping the condition and the evidence is the inverse fallacy.

Reading "if they have it" sounds like a fact about the condition, which is what a prior feels like. This statement is about the test's behavior when the condition is already present. That is a likelihood, not a prior.

That would be the false-positive rate. The statement was about people who have the condition. Mixing those two rates swaps the rows of the test's table.

4. The same person tests positive a second time, on a test that fails independently of the first. What should you use as the prior for that second update?

After the first result, the posterior is what you now believe. That becomes the prior for the next independent result. You do not walk back to the population rate.

Restarting each test makes each one seem to begin from the same population figure. The second test is new evidence about the same person. The first result already changed what you should believe, and discarding it throws away evidence you have.

Resetting from the accuracy percent treats the only number on the test as a fresh prior. Accuracy is not a prior. Using it as one treats a property of the test as a property of the person.

Blending two results treats them like two scores. Bayes' rule does not average the labels. It updates a probability with each likelihood.

5. For two hypotheses you multiply likelihood by prior and get 0.4 and 0.4. You stop. What is wrong with stopping?

0.4 and 0.4 still have to be divided by everything those hypotheses can produce together (0.8 if they are the only two). Each posterior is then 0.5. Skipping that division leaves numbers that are not probabilities.

Stopping after each multiplication treats 0.4 as a finished probability. A set of posteriors for hypotheses that cover the possibilities has to add to 1. Unnormalized products do not.

Adding the pieces feels like the combine step the rule asked for. The sum is the marginal probability of the evidence, the divisor. It is not the posterior of the first hypothesis.

Keeping only the likelihood treats the data term as the only part that should survive. Dropping the prior is not Bayes' rule. And the larger likelihood, by itself, is not a posterior.
