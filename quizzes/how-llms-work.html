How LLMs work

Misconception quiz

Five questions on how large language models produce text. Every wrong option is a misconception people actually hold. Pick one. The note says why that choice was tempting, and what is going on instead.

1. At one step, before any new word appears, what does a large language model produce?

The model scores every token it knows, turns those scores into probabilities, and then one token is chosen from that distribution. The paragraph is that step repeated, not a document fetched whole.

Watching a whole answer arrive makes the paragraph seem stored. The model did not emit the paragraph as one stored object. It committed to one token at a time.

Reading a confident reply makes the step seem to have had a single certain output. The step always has a distribution. Even a sharp distribution still assigns probability to other tokens.

Fluent prose looks like the result of a search. This step does not return pages. It returns token probabilities. Looking documents up would be a different system bolted on beside the model.

2. You ask a question and get a fluent paragraph back. Where did that paragraph come from?

Specific prose that arrives fully formed looks like a system retrieved it from a file. A standard language model is not reading a stored question-and-answer entry. Each token was chosen from a distribution that depends on the tokens already in the context.

Training shaped those distributions. At answer time the model does not search a cabinet of finished replies. It extends the context one token at a time.

Search boxes produce a result that way, and the paragraph may resemble something that exists elsewhere. Resemblance is not a live copy step. Unless a separate retrieval tool was added, the model is not opening a page when it answers.

Shared answer shapes make a form letter seem to be sitting behind them. A shared shape can be a likely pattern in the next-token distributions. It is not a stored form with blanks the model fills from a record.

3. The sampling temperature is set near zero. What happens on the next token?

Near zero, sampling collapses onto the most likely token. The reply is nearly the same from run to run because that top token wins almost every time, not because a record was fetched. Small numeric differences can still change a rare step.

Repeatable replies look retrieved. Repeatability here is the choice of the top token. The model is still scoring the vocabulary, then taking the winner.

Stable answers feel verified. Temperature does not add a fact check. Nothing in this step compares the token to a document.

Blending the candidates feels like what a distribution asks you to print. The model does not print a blend. It picks a token. Near zero, that pick is the most likely one.

4. A next-token prediction follows an instruction that appeared much earlier in the prompt. How is that possible?

Attention is a weighted use of the earlier tokens in the context, not a second mind checking facts. Training can make "continue by doing what that text asked" a high-probability pattern. The prediction can still be wrong.

Following a long instruction looks like executing a saved procedure. The instruction is in the context. The model conditions on it. It does not open a plan by name.

Noticing the instruction and the answer as two blocks makes the answer seem written first and checked second. The instruction is already in the context when later tokens are predicted. There is no later search pass in a plain next-token model.

Relevant replies feel like understanding. Attention moves probability toward tokens that fit the context. It is not a person deciding what is true.

5. The same prompt returns two different replies. What can explain that, with no one changing the model in between?

When temperature is above zero, each step draws from the probabilities instead of always taking the top token. A different draw early on sends the context down a different path. Two replies do not require two stored essays.

Two coherent replies look like two records in a file. The model did not alternate between saved answers. It sampled.

Different output seems to require a different machine. The weights stayed put. The variation is in the sampling, not in a rewrite of the parameters.

Preferring the first reply makes the second one look like noise. Both replies are draws from the same kind of next-token distribution. Neither one is a lookup of a single stored fact.
